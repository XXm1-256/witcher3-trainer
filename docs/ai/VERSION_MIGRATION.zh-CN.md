# AI Agent游戏更新与地址迁移教程

## 哪些地址会变

| 数据 | 变化时机 | 正确处理 |
|---|---|---|
| PID、模块基址 | 每次启动，ASLR影响基址 | 重新读取，`VA=基址+RVA` |
| 玩家、背包、容器、引用、返回数组指针 | 生成、读档、切场景和进程生命周期 | 重新解析并检查类型/身份，不能保存成固定偏移 |
| 函数、虚表、全局变量RVA | 重新编译和版本更新 | 逐个定位语义入口，不能整体平移 |
| 字段偏移、布局、标志、ABI、参数位置 | 新二进制可能改变 | 即使RVA不变也核对元数据和指令 |
| 名称数字ID、CFunction和RTTI地址 | 进程/版本相关 | 按名称重新解析注册元数据 |
| 物品/能力名称和资源元数据 | 通常稳定但没有保证 | 核对安装的本体/DLC资源及类型 |
| Hook页、请求标志、对象所有权 | 某次注入及其进程 | 核对标记、代码与拥有者，禁止跨进程迁移 |

ASLR基址变化和游戏更新是不同问题。旧RVA只有在布局/版本校验成立时才可复用；堆指针不能靠新基址重建。

## 工程中的真实例子

GameVersion将旧参考RVA映射至5.00c：

| 项目 | 参考RVA | 5.00c RVA |
|---|---|---|
| FactsAdd | 0x1F5CEF0 | 0x1F58700 |
| 原生入口 | 0x2050950 | 0x204C140 |
| 全局数据 | 0x5CC5440 | 0x5C9E408 |
| 数组析构 | 0x26FC970 | 0x26FC970 |

变化量不同，部分完全不变，禁止统一加减一个差值。FactsAdd曾错误候选0x1F58600，实际是函数内部位置，调用导致崩溃；0x1F58700通过实际注册与指令核对确定。地址接近不能作为入口证据。

当前哈希命中5.00c配置；未知哈希走旧参考分支，**不能据此宣称适配未知版本**。Agent适配新版本，须在写入前独立确认语义入口/布局。产品不必仅因哈希不同弹窗，但具体操作校验必须保留。

## 迁移步骤

1. **指纹**：记录exe SHA256、大小、架构、渲染器、版本；本地只读副本用于离线分析，游戏本体不上传。保留存档与独立分析资产。
2. **语义锚点**：按注册原生/脚本名称、配置键、类与属性名称找交叉引用，再沿注册找到真正函数指针。参考ResolveName、LootGlobalFunction、RespecProperty、FunTarget及调度器元数据读取代码。
3. **入口核对**：追踪已确认的call/jump跳板，核对PE区段范围。反汇编候选，确认序言、控制流、调用约定、注册参数数量和类型。字符串附近地址或零散字节匹配不充分。
4. **特征码**：选有语义的指令，通配相对call位移、RIP相对地址和重定位；只扫描正确可执行区段，要求唯一匹配，并用独立注册/类型锚点交叉确认。零个/多个匹配均是未定位。
5. **布局核对**：检查CFunction所属类、标志、属性类型、参数偏移、返回类型、脚本/原生选择；检查玩家/背包虚表、引用寿命和容器类。旧偏移只是待验证假设。
6. **Hook审核**：覆盖完整指令；正确处理RIP相对操作数和分支；核对原字节、页标记、拥有者、页容量、寄存器、栈对齐、返回地址。不能扩大匹配范围凑通过。
7. **新配置**：每项入口都有映射、期望字节及依据；保留旧配置历史，不能统一平移或仅改哈希声称成功。
8. **离线验证**：中英文构建，本地二进制特征匹配、字节码改写不变量、元数据解析和请求状态检查；确认翻译没改hex常量、原生ID与资源语义。
9. **只读实机**：依照当前授权重新读取对象、注册和类型，核对整个读取过程的进程身份。只读回读不能替代调用安全证明。
10. **隔离写入**：取得玩家明确许可与存档，一次验证独立功能，分别确认请求完成、游戏效果和需要时的存档持久化；恢复临时开关。崩溃或校验失败时停止并保留诊断。

## 暂停和所有权

游戏线程处理调度任务，菜单和读档可能延迟。区分pending=1、running=2、completed；超时不等于未执行。取消边界暂停线程后检查完成状态，只取消未开始请求；已经执行的等待完成，不能复用缓冲区。

拾取返回数组在析构确认完成前保留所有权，下一轮先清理；进程身份变化才丢弃旧进程记录。场景未就绪保留开关意图，未知代码/类型错误停止。禁止重复析构或跨进程复用引用。

## 每项迁移的证据模板

```text
功能/语义名称：
旧exe哈希、配置、参考RVA：
新exe哈希、渲染器、新RVA：
注册/类型锚点：
特征码、掩码、匹配数、区段：
反汇编入口和原字节：
所属类、ABI、参数、偏移、返回类型：
引用寿命和清理：
验证层级：离线/只读/写入/玩家观察/存档读回：
失败、具体适用范围、重新验证所需依据：
提交、成品哈希、待解决事项：
```

记录带指纹的RVA，不把现场绝对VA描述成通用地址。重开失败路径要有能回应其原因的新证据，例如正确注册、有效指令入口、兼容元数据或明确生命周期处理。
